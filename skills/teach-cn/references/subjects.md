# 分学科处理

三条通用规则之外，不同学科的知识链形态、可核验程度与图示需求差别很大。以下按学科给出差异化约定。

## 一、数学与物理

**知识链形态。** 依赖树最深且最刚性，前置缺一不可。摸底必须沿多条链分别二分，尤其要把「记号能认出」与「条件能用对」分开测：前者常常掩盖后者的空白。

**教学展开。** 以 `定义 → 定理 → 证明骨架 → 例` 为主轴。证明给骨架而非全文：说明关键引理与它们如何拼接，把可机械验证的部分留作习题。物理主题额外要求给出量纲检查与极限情形检查，这两项本身就是理解的一部分。

**记号。** 首次出现的每个记号都要说明读法、来源与常见的记号冲突。文献中记号不统一时明确指出，并声明本次会话采用哪一套。同一术语有多种通行中译时（如余向量、协向量、对偶向量）首次出现并列给出，之后固定用一种。

**图示。** 优先生成 SVG，用 `write` 写入附件目录后在笔记中嵌入。生成后用 `read` 重新读取该 SVG 的源码做一次源码级检查：逐个核对元素坐标是否落在 `viewBox` 范围内，各 `<text>` 的包围矩形（按 x、y、字号与字符数估算，每个汉字约一个字号宽、每个拉丁字符约 0.6 个字号宽）是否互相重叠，每个箭头的起止端点方向是否与文字描述一致。pi 的 `read` 只把 JPEG、PNG、GIF、WebP、BMP 识别为图片，SVG 按普通文本读回，你看到的是 XML 源码而不是渲染结果，检查只能基于数值推算，不要声称「看到了图」。视觉效果请学习者在 Obsidian 中确认后再写入日志。概念之间的关系用 mermaid，不要用 SVG 画关系图。

**习题。** 一道计算题加一道概念辨析题。概念题优先考察「条件去掉后会怎样」。

## 二、编程与计算机科学

**知识链形态。** 至少分三条独立的链：语言与语法、系统与理论概念、工程实践与工具链。学习者在其中一条上很强而另一条上是空白是常态，摸底不要因为一条链上的表现而推断另一条。

**教学展开。** 例子必须可运行。可以用 `write` 写出最小示例，用 `bash` 或 `powershell` 实际执行并把真实输出贴回讲解中。真实输出与预期不符时，这个不符本身就是最好的教学材料，不要掩盖。

**安全约束。** pi 没有沙箱，`bash` 与 `powershell` 工具直接在真实环境中执行。仅在学习目录内创建与运行文件；不执行任何有副作用的操作，包括安装依赖、修改学习目录之外的文件与发起网络请求；确有必要时先向学习者说明并等待同意。

**图示。** 用 mermaid 表达调用流程、状态机、模块依赖与时序。数据结构的内存布局用 SVG 或等宽字符图。

**习题。** 优先「预测输出」与「改错」两类，而不是「从零实现」。前两类能精确定位理解缺口，后者耗时且反馈稀疏。

## 三、其他学科与通识主题

**知识链形态。** 依赖关系较弱，但概念边界模糊，容易出现「术语都认识、区分不出来」的状态。摸底应侧重辨析题：给出两个相邻概念的具体情境，问该判为哪一个。

**事实核查权重最高。** 每一个实证性断言都要标注其确立程度，见 `references/fact-check.md`。涉及数据、时间、人物、机构、法规与政策的具体陈述，若无法核验，讲授时必须显式标注「未核验」，或干脆略去。

**教学展开。** 主轴是概念区分与常见误解，而非推导。每个节点应包含一条「这个概念常被与什么混淆，区别在哪里」。存在学派分歧时，分别陈述各方立场与其证据基础，不要给出裁决。

**图示。** mermaid 关系图与时间线为主，避免用图示为本身不精确的关系制造精确感。

**习题。** 辨析题与「给定情境判断适用哪个框架」两类。
