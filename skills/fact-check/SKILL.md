# 断言核查

对给定的每条断言，逐条输出以下五项，不要合并成散文。

**一、断言重述。** 把原话改写成一个可判真假的命题。若原话包含多个断言，先拆开逐条处理。若原话因含糊而无法判真假，指出含糊之处并给出两三种可能的严格读法，请提问者选择。

**二、类别。** 归入下列之一：定义或约定；已确立结果；启发式（有已知反例或适用范围限制）；猜想或开放问题；有实质争议。

**三、判定。** 按类别与内容给出相应处理：

- 属于数学或逻辑内部的，归约到定义直接验证，或构造反例。真做验证，不要以「这是标准结果」代替。
- 涉及文献归属（标题、作者、年份、期刊、DOI）、术语与人物与日期、软件版本的，按 `references/verify.md` 用 `bash` 经 `curl` 查免密钥的公开 API；只有学习目录 `AGENTS.md` 安全边界清单内的渠道不必逐条征得同意。文献要标题、作者姓氏、年份三者同时对上才算核实。
- 其它实证性断言，若已安装 `brave-search` 等联网检索技能则检索并给出来源；否则标注「未核验」，并说明应当查证什么、去哪类资料中查。

**四、来源。** 列出核实所用的来源及其等级（原始文献或官方文档、综述或教材或百科、一般网页）与检索日期；来源相互矛盾时如实并列，不择一。无来源写「未核验」。

**五、失效条件。** 该断言在什么条件下不再成立，或其适用范围的边界在哪里。这一项往往比判定本身更有价值。

## 禁止

编造文献、页码、定理编号、作者、日期或统计数字。以「一般认为」「研究表明」代替来源。把记忆中不确定的内容以确定语气陈述。把 API 查不到当作「不存在」的证据：查不到只能记「未核验」。

无法核实是一个合法的结论，含糊其辞不是。

## 语言与风格

书面正式语体，中文全角标点，不使用感叹号、emoji 与鼓励性套话。
